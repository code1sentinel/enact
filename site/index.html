Enact

GitHub Codify

OSCAL controls become runnable checks, then assessment results.

Enact is a local Python CLI. It loads an OSCAL catalog plus a check manifest, runs OPA/Rego (and records manual or hybrid work), and writes NIST OSCAL 1.1.2 assessment results and POA&M items — with HTML and Markdown reports. Nothing leaves the machine.

OSCAL controls

Catalog, profile, or component-definition. Parameters stay in OSCAL.

→
Runnable checks

A manifest maps each rule_id to a control_id, engine, and type.

→
Results and POA&M

OSCAL assessment-results JSON, POA&M items for automated failures, plus reports.

Bundled example, generated by Enact

These files are produced in GitHub Actions by running enact run on examples/access-control/. They are not hand-written. Open the HTML reports, or the raw OSCAL JSON.

Passing IAM config

Review every 30 days, lockout after 3 tries, privileged review every 14 days — all inside the OSCAL thresholds.

2 passed 2 need evidence 0 POA&M items

Two automated checks pass. The manual access-agreement control stays not automated. The hybrid privileged-review check still needs evidence — that is not a failure.

Failing IAM config

Review every 180 days, lockout after 20 tries, privileged review every 365 days — all over the catalog limits.

Automated and hybrid failures become findings and POA&M items. The manual control still does not fail.

What the example checks

Four access-control statements in the Codify catalog shape. Thresholds live in OSCAL params; Rego reads input.oscal_params.

Control Rule Type What it looks at
c-ac-2 ac-account-review automated Account review cadence vs. 90 days
c-ac-7 ac-login-lockout automated Lockout threshold vs. 5 failed attempts
c-ac-8 ac-access-agreements manual Signed agreements — recorded, never failed by the engine
c-ac-2p ac-privileged-review hybrid Privileged review cadence, plus reviewer sign-off

Install and run

Python 3.10+ and the OPA binary (1.8.x, Rego v1) on PATH. ENACT_OPA overrides the binary path.

  1. Clone the repo and install Enact.
  2. Run the passing and failing example configs.
  3. Validate the OSCAL JSON against the vendored NIST 1.1.2 schemas.
git clone https://github.com/code1sentinel/enact.git
cd enact
pip install -e ".[dev]"   # or: uv sync --extra dev

enact run \
  --oscal examples/access-control/catalog.json \
  --manifest examples/access-control/manifest.json \
  --input examples/access-control/inputs/passing.json \
  --workdir examples/access-control \
  --out out/pass \
  --title "Access-control example (passing)"

enact run \
  --oscal examples/access-control/catalog.json \
  --manifest examples/access-control/manifest.json \
  --input examples/access-control/inputs/failing.json \
  --workdir examples/access-control \
  --out out/fail \
  --title "Access-control example (failing)"

enact validate \
  --assessment-results out/pass/assessment-results.json \
  --poam out/pass/poam.json \
  --catalog examples/access-control/catalog.json

enact serve out/pass

The failing run exits 1. That is expected: automated failures are the signal, not a broken CLI.
