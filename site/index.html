What is Enact? Codify writes the catalog; Enact runs the checks. Codify exports OSCALA standard way to write security controls as files so tools can share them.; Enact runs Catalog → Checks → Evidence → Run in this tab, then you download assessment results. Nothing leaves your browser.

How to use it

  1. Catalog — use the example or open a catalog JSON in this tab.
  2. Checks — review the checks that apply, or open your mapping file.
  3. Evidence — open a local settings JSON, or a passing/failing sample.
  4. Run — evaluate here, then download the results and the HTML report.

        Advanced — CLI, CI, and custom checks
        
      For engineers: install locally to write your own checks or run Enact in GitHub Actions. Custom checks? Use the Enact CLI.
      
        
      Power users and pipelines can install Python 3.10+ and OPA 1.8.x, then use enact ui on localhost or enact run in CI. Custom / draft RegoThe language used to write an automated check for OPA. stays on this path.
      

      git clone https://github.com/code1sentinel/enact.git
cd enact
pip install -e ".[dev]"   # or: uv sync --extra dev

enact ui
      
        
      The same runner for scripts and GitHub Actions:
      

      enact run \
  --oscal examples/access-control/catalog.json \
  --checks examples/access-control/checks.json \
  --input examples/access-control/inputs/passing.json \
  --workdir examples/access-control \
  --out out/pass \
  --title "Access-control example (passing)"

# Or pass the C2P-shaped Component Definition as the mapping
enact run \
  --oscal examples/access-control/catalog.json \
  --oscal examples/access-control/component-definition.json \
  --input examples/access-control/inputs/passing.json \
  --workdir examples/access-control \
  --out out/pass-cd
      
        
      The failing run exits 1. That is expected: automated failures are the signal.
